# Vesora v0.8 measurements

Measured on 2026-10-14 on Windows 11 with an Intel Core i9-14900HX. These are synthetic workload checks, not universal latency or FPS guarantees. Source data, browser/renderer identity, runtime hashes and raw completion samples accompany the measurements.

## Python host streaming

Both producers start with three curves containing 100,000 Float64 rows each, retain that capacity, and submit 100 batches of 100 rows per curve at a requested 20 Hz. The curve is `(series+1)*0.15 + 3*exp(-x/2000) + 0.08*sin(0.07*x+series)`. The retained numeric payload is 4,800,000 bytes. The requested figure size is 900 × 520; notebook layout is responsive to its cell.

Latency starts before Python accepts a batch and ends when the renderer acknowledges a revision covering it. It includes Python validation, binary transport, JavaScript append/planning, draw submission and the returning acknowledgement. Initial construction and PNG export are excluded. This is application readiness, not a measurement of physical display presentation. Later updates can share a covering frame. p95 is nearest rank, sample 95 of 100 sorted completions.

| Host | Reported renderer | p50 | p95 | Maximum | Completed batches/s, including final drain |
| --- | --- | ---: | ---: | ---: | ---: |
| QtWebEngine | Intel UHD / ANGLE D3D11 | 76.34 ms | 131.21 ms | 182.09 ms | 19.81 |
| JupyterLab | ANGLE SwiftShader / Vulkan | 143.40 ms | 235.08 ms | 297.50 ms | 19.40 |

Both p95 results meet the proposed 300 ms host target for these runs. Actual throughput is reported rather than rounded up to the requested 20 Hz. The Qt and notebook GPU paths differ, so their timing ratio does not isolate transport overhead. Qt reported hardware rendering despite software-renderer launch flags; classification follows the renderer string.

Python was 3.14.6. [Qt raw samples](v0.8.0/qt-streaming.json) and [Jupyter raw samples](v0.8.0/jupyter-streaming.json) retain every latency. The full real Jupyter integration test completed all 16 cells in 60 seconds, including frozen exports, burst deltas and widget redisplay. Its functional results are separate from the 100-sample timing case.

The final wheel was also installed outside the checkout with PySide6 6.12.0, aiohttp 3.14.5, anywidget 0.11.0, ipykernel 7.4.0 and JupyterLab 4.6.4. The same 100-batch workload measured Qt p95 **137.73 ms** at **19.66 batches/s** and Jupyter p95 **147.83 ms** at **19.72 batches/s**. These are separate validation runs with a different host dependency environment, not paired evidence of a host speedup. [Installed Qt samples](v0.8.0/installed-qt-streaming.json), [installed Jupyter samples](v0.8.0/installed-jupyter-streaming.json) and [package-origin evidence](../releases/v0.8.0/installed-host-verification.json) record the results.

## Browser regression method

`scripts/benchmark-v08.mjs regression` compares the locally packaged v0.7 runtime with v0.8 on the same machine and browser. Each of five paired repeats measures 1M-point Gaussian density and a 1M-point monotone-x line. Runtime order alternates by repeat. Each measured case uses a fresh page, 1000 × 600 actual drawing-buffer pixels at DPR 1, and 100 distinct viewport changes. A small unmeasured points+density figure warms each runtime first. Data generation precedes the first-ready timer.

The density generator is an LCG with seed 42 and Box–Muller pairs. Lines use `x=i/1000` and `y=sin(x)+0.1*sin(17*x)`. View order uses `(i*7)%100`, a permutation of all 100 states. Both runtimes receive identical input, dimensions and view operations. First ready includes source registration, validation, layout, worker setup and draw submission. Interaction p95 uses nearest rank, sample 95 of 100. Percentage changes use **ratio of medians**, `(median(v0.8) / median(v0.7) - 1) × 100`.

The baseline is extracted from `dist/release-v0.7.0/vesora-core-0.7.0.tgz`; its index SHA-256 is `8e041ef2115d0cf937dfa100477e35c2c826a57ea576f06cf52b7dec29781486`, matching the [v0.7 report](v0.7.0.md). It includes the existing v0.7 working-tree work and is not reconstructed from the older repository HEAD. Both baseline and current worker files must be present.

Chrome **155.0.8059.41**, Windows 11, Intel Core i9-14900HX; actual canvas **1000 × 600 at DPR 1**. Software rendering reported ANGLE SwiftShader/Vulkan; the default path reported Intel UHD/ANGLE D3D11. Each number below is the median of five repeats. Negative changes mean lower latency.

| Renderer | Workload | First ready v0.7 → v0.8 | Change | Interaction p95 v0.7 → v0.8 | Change |
| --- | --- | ---: | ---: | ---: | ---: |
| SwiftShader | 1M density | 184.0 → 186.9 ms | +1.58% | 230.1 → 228.0 ms | −0.91% |
| SwiftShader | 1M line | 171.1 → 168.7 ms | −1.40% | 202.8 → 187.9 ms | −7.35% |
| Intel UHD | 1M density | 148.2 → 156.9 ms | +5.87% | 82.7 → 83.3 ms | +0.73% |
| Intel UHD | 1M line | 144.2 → 149.5 ms | +3.68% | 82.8 → 75.9 ms | −8.33% |

All ratio-of-median changes are within the proposed **15% maximum regression** gate for this machine and workload. This does not mean every individual trial improved: the first hardware density pair had p95 values of 202.2/207.9 ms, while later repeats were about 81–84 ms. Those samples remain in the reports. The line interaction improvement accompanies a modest hardware first-ready cost.

[Software raw results](v0.8.0/regression-software.json) and [hardware raw results](v0.8.0/regression-default-gpu.json) contain all 20 measured cases per renderer and every interaction sample. ## Browser streaming method

`npm run benchmark:streaming` runs the same three synthetic curves with 100,000 retained rows each, 100 rows per batch and a 20 Hz timer for 60 seconds. Appends can overlap and are acknowledged by a covering frame. The harness records all completion latencies, actual throughput, maximum pending promises, deferred producer ticks, source/cache/geometry counters and available main-page JS heap samples. Deferred ticks count explicit producer deferral at 63 pending promises; delayed browser timers can reduce actual throughput without incrementing that counter. It checks retained row identities, source bytes and drained append waits. The final drain has a 30-second timeout and errors are saved with the report.

`node scripts/benchmark-v08.mjs soak` uses the same workload for 30 minutes. `VESORA_SOAK_SECONDS` overrides duration. Set `VESORA_SOFTWARE_GPU=0` to request the normal GPU path; the default requests SwiftShader. Classification must follow the recorded renderer. Other project graphics tests/builds are stopped during browser performance runs. OS scheduling, thermal state and unrelated background processes are not controlled.

Heap samples are available main-page JavaScript heap, without forced GC; they exclude worker, Python, native browser and GPU memory and include the harness's retained latency samples. Canonical source-byte plateaus establish retained payload bounds, not total resident-memory bounds or exact backing-buffer allocations. Frozen exports and application-owned history are separate allocations. A browser soak does not establish a 30-minute Qt/Jupyter soak result.

The harness writes raw JSON to `artifacts/v08/`; selected evidence is retained beside this report. Use [the development guide](../development.md#validate-v08-streaming-and-compatibility) to reproduce release and host checks.

## Browser streaming results

The 60-second runs used the same Chrome, actual canvas and runtime hashes as the regression comparison. Initial construction is excluded. Latency measures atomic three-series append submission to the covering ready promise; the timer submits independently of that promise.

| Reported renderer | Batches | Actual batches/s including drain | Append p95 | Maximum pending | Deferred ticks | Errors |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| SwiftShader/Vulkan | 1,200 | 19.986 | 26.5 ms | 1 | 0 | 0 |
| Intel UHD/D3D11 | 1,200 | 19.986 | 25.4 ms | 1 | 0 | 0 |

Both meet the proposed **150 ms browser p95** target. Each layer finished with 100,000 retained rows, sequence 220,000 and 120,000 evicted rows. Canonical source and worker-source counters were each 4,800,000 bytes. The final append queue drained to zero; closing released canonical sources and stream state. [Software samples](v0.8.0/stream-software.json) and [hardware samples](v0.8.0/stream-default-gpu.json) contain all 1,200 latencies and resource counters per run. These smooth, monotone-x curves do not establish the same performance for arbitrary scatter distributions.

## Thirty-minute browser soak

The Intel UHD/D3D11 run completed in **1,800.038 seconds**, including the final drain, with **35,965 accepted and completed batches**, **19.980 batches/s**, **zero append/drain errors** and **zero explicit producer deferrals**. This is 10,789,500 new rows across the three curves. The browser timer produced fewer than the nominal 36,000 batches; accepted batches were all accounted for.

| Measure | Observed result |
| --- | ---: |
| Append p50 / p95 / p99 | 22.8 / **70.7** / 141.4 ms |
| Slowest append | 332.0 ms |
| Maximum pending append promises | 6 |
| Pending appends after final drain / close | 0 / 0 |
| Completed frames | 35,457 |
| Final requested / committed revision | 35,967 / 35,967 |
| Retained rows per curve | 100,000 |
| Final next sequence / evicted rows per curve | 3,696,500 / 3,596,500 |
| Canonical source / worker-source counters | 4,800,000 / 4,800,000 bytes at every sample |
| Final query cache / estimated geometry bytes | 43,084 / 1,772,736 |
| Main-page heap sample range | 16.90–71.52 MB |
| First five-minute heap minimum / last five-minute minimum | 16.90 / 17.21 MB |

The run meets the **150 ms p95** target, though individual appends exceeded it. A transient backlog around 17.5 minutes returned to one pending update by the next 30-second sample. Several updates shared covering frames, so completed frame count is lower than accepted batch count. Final state identities, retained counts and sequence totals passed the harness assertions.

The retained payload stayed bounded and sampled heap returned repeatedly to about 17 MB. This is evidence for this workload, not a proof of bounded total process/GPU memory or absence of every leak. The final five-minute heap range was 17.21–64.97 MB, with the harness retaining all completion samples. Closing reported zero canonical source bytes, zero pending appends and no stream states. Worker traffic was cumulative 6,820,790,784 bytes over the run; this counter measures transfer volume, not resident allocation.

[Full soak evidence](v0.8.0/soak-default-gpu.json) contains every completion latency, 30-second resource samples, final states and runtime/worker hashes. The machine reported 34,045,042,688 bytes of physical memory. Qt/Jupyter have the shorter executed integration measurements above; they were not subjected to this 30-minute soak.
