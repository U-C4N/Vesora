# Vesora v0.3 panel benchmark

This is one observed run of the reproducible panel benchmark, not a speed guarantee or comparison against other libraries.

## Environment and method

- CPU: Intel(R) Core(TM) i9-14900HX; 32 logical CPUs; 31.7 GiB system memory.
- Platform: win32 / x64; headless Chrome 154.0.8037.98.
- Reported renderer: `ANGLE (Intel, Intel(R) UHD Graphics (0x0000A788) Direct3D11 vs_5_0 ps_5_0, D3D11)`. Software GPU was not requested.
- Viewport: 1,000 × 800 pixels at device pixel ratio 1.
- Each row count is the **total per figure**. Four-panel figures split it equally across panels; both axes are linked.
- Lines use a monotonic-x synthetic signal. Scatter uses Gaussian samples generated with a fixed seed.
- Each case opens a fresh page in the same browser. First render includes figure/source preparation, worker startup and drawing, but excludes synthetic data generation. Startup and compilation costs can vary across cases.
- Zoom samples measure 20 programmatic view changes through `ready()`. No warm-up samples are discarded. Heap is the browser's JS heap estimate at the end of the case; GPU and Python memory are not measured.

All eight cases finished with WebGL error code 0. These measurements compare different panel layouts and representations under a fixed input-row budget. They are not rendering FPS and do not establish a universal multi-panel speedup.

## Reproduce

```bash
npm run build
npm run benchmark:panels
```

The complete report is written to `artifacts/benchmark-panels.json`, including every latency sample, source sizes, representation metadata and environment. Set `VESORA_SOFTWARE_GPU=1` to explicitly measure SwiftShader and keep those results separate from hardware runs.
