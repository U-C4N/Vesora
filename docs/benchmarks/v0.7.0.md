# Vesora v0.7.0 regression measurements

Measured on 2026-10-13 using the same machine, browser, synthetic data and viewport for v0.6 and v0.7. Software and hardware GPU results are separate. No metric reproduced a regression above 15% in all three trials; the largest median increase was 9.6%. Individual trials fluctuate, including isolated increases above 15%, so this is a release regression check rather than a general speed guarantee.

## Environment and method

- Windows, Intel Core i9-14900HX; headless Chrome 155.0.8059.40.
- Browser viewport 1200 × 900; figure 1000 × 600 logical pixels; DPR 1.
- Software renderer: `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)`.
- Hardware renderer: `ANGLE (Intel, Intel(R) UHD Graphics (0x0000A788) Direct3D11 vs_5_0 ps_5_0, D3D11)`.
- v0.6 baseline: runtime built before edits from commit `60a945d9d20b55050556929c5ee7276fa5244f97`. Runtime SHA-256: `e9cf40ea02fc031cb40387018667478be795084e22acfe886e018f9183fc921a`.
- v0.7 working-tree runtime SHA-256: `8e041ef2115d0cf937dfa100477e35c2c826a57ea576f06cf52b7dec29781486`.

Each browser session first renders one unmeasured figure with points and density to warm the driver/program. Each measured case uses a fresh page. Three repeats run density then line, first for v0.6 and then v0.7; tests, builds and other benchmark jobs are not run concurrently. OS scheduling and driver caches are not fully reset. The initial exploratory cold-driver measurement is retained locally but is not mixed into this comparison.

Both cases have 1,000,000 Float64 rows. Density uses deterministic Gaussian pairs from an LCG seeded with 42. The line uses `x=i/1000`, `y=sin(x)+0.1*sin(17*x)`. Data generation precedes the first-ready timer. First ready includes figure creation, source validation, worker setup, layout and draw. Each case then performs the same 20 `setView`/`ready` operations. Interaction p95 uses nearest rank, sorted sample 19 of 20; it is not FPS or pure GPU time. Source arrays and scene meaning are unchanged between versions; the new measured layout can change plot margins and density bin counts.

## Reproduce

Build the baseline revision in a separate checkout and copy its `packages/core/dist/index.js` and `worker.js` into `artifacts/v07/baseline-runtime/` in the current checkout. Build the current version, then run these commands sequentially while other graphics workloads are idle:

```powershell
$env:VESORA_SOFTWARE_GPU='1'
node scripts/benchmark-quality.mjs baseline-v06-software /artifacts/v07/baseline-runtime/index.js
node scripts/benchmark-quality.mjs v07-software
$env:VESORA_SOFTWARE_GPU='0'
node scripts/benchmark-quality.mjs baseline-v06-default-gpu /artifacts/v07/baseline-runtime/index.js
node scripts/benchmark-quality.mjs v07-default-gpu
```

The script owns a temporary server on port 4187 and writes JSON under `artifacts/v07/`. `VESORA_CHROME` can select the browser executable. Always compare the reported browser, renderer and runtime hashes. These measurements exclude Python/Qt/Jupyter transport, PNG encoding, total/peak memory, x-hover latency and band rendering performance; those features have separate functional tests.
