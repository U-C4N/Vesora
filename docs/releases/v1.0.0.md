# Vesora 1.0.0

Core, React and Python release identities are 1.0.0. This page records the implementation, verification scope and publication policy. The [GitHub release](https://github.com/U-C4N/Vesora/releases/tag/v1.0.0) records final downloadable assets and registry publication status.

Added families: ECDF/CCDF, supplied spectrogram with bounded rows, event timeline, asymmetric error bars, contour/filled contour, quiver, parallel coordinates, Pareto, phase portrait/hysteresis and ternary. Protocol 9 preserves their source values/options; protocols 1–8 remain readable.

The portable `skills/vesora` skill includes host references and runnable three-language examples. `llms.txt` is the compact LLM documentation entry point.

`npm run verify:next` supplies one maximum-ten-minute automatic check including build, archives, real browser/offline and installed-wheel Qt/Jupyter workflows. Success needs an actual report under `artifacts/v1-verification`; incomplete runs fail. Historical endurance/human evidence is neither changed nor inferred.

`npm run package:release -- --candidate` writes `dist/release-v1.0.0`. Local candidate files cannot be published by the existing guarded publisher. The verifier does not create tags, commits, uploads or publication claims.

See the [API guide](../v1.md) and [verification contract](../verification-v1.md).

## Approved v1 publication policy — 5 November 2026

The owner explicitly approved publication using the minute-scale automatic v1 checks, with unfinished long-duration and human tests disclosed in the release notes. The `v1-bounded-automatic` policy applies to **major version 1 only**. It requires seven genuinely completed, reviewed gates bound to the final clean, tagged archives:

| Required gate | v1 evidence scope |
| --- | --- |
| `correctness` | Core/React/Python contracts, types, parity and executable skill examples. |
| `browser` | Real WebGL2 browser, application/tour flows and offline source/export checks. |
| `qt` | The exact installed wheel's real QtWebEngine rendering/export and cleanup workflow. |
| `jupyter` | The exact installed wheel's real two-cell JupyterLab widget workflow and cleanup. |
| `reactConsumers` | Independently installed React 18.3/19 Vite and Next consumers using the final package archives. |
| `packages` | Final package/runtime/checksum integrity, metadata and isolated installed-package consumers. |
| `performance` | Fixed short workloads with recorded environment, workload, durations and resource cleanup. |

**Explicitly unverified:** long-duration endurance (including the historical two-hour soak), real screen-reader/human accessibility evaluation, and the five-person unaided beta pilot. These are disclosed as `unverifiedScopes` in the release gate policy; they are not passed gates, certifications or claims. The bounded Qt/Jupyter workflows do not establish the older long-duration host/recovery criteria, and short performance probes do not establish endurance.

The publisher derives requirements from the release version and requires matching policy metadata in v1's `release-gates.json`. It rejects a missing automatic gate, stale archive evidence, omitted disclosures or invented human/endurance gate entries. Version 0.x and existing RC archives retain all ten historical requirements and their original evidence format. No historical failure is erased or relabelled.

Run `npm run verify:next` **before** final packaging: it produces local candidate archives. Final publication needs `npm run package:release` from the clean matching tag without `--candidate`, followed by direct verification of those exact archives and their gate reports. Upload success remains separate from exact-version download/hash/installed-consumer verification.
