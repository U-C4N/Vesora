# Vesora 1.1.0

Core, React and Python release identities are 1.1.0. This page is the source note for that version. It does not mean 1.1.0 was already on npm or PyPI. The [GitHub release](https://github.com/U-C4N/Vesora/releases/tag/v1.1.0) is where downloadable assets and registry publication status belong. [1.0.0](v1.0.0.md) remains the previous release.

1.1.0 keeps scene protocols 1–9 and the 1.0.0 analysis families. The additions are viewer and interaction behavior:

- The shared viewer command bar holds the view actions, a status pill, and one Export menu. The pill reads Live, Frozen snapshot, or Ready. While frozen, it includes the capture time. Export writes PNG or HTML from the displayed frame or the latest accepted data, with a checkbox for the observation record. The full-width Export options row is gone.
- The sample card can take keyboard focus. It shows the layer, coordinates, the unit when one is declared, the source index, and the representation method when available. Revision, byte, and worker details stay in a collapsed Details disclosure. A theme change while frozen updates the chrome immediately and applies the plot theme when the view returns to live.
- Line, band, and spectrogram panels that share a linear or time x axis, and a single panel of those kinds, show an x-range strip under the plot. Dragging sets the x domain, and a double-click clears it.
- When axes share x, the cursor shows each line's nearest recorded sample from x inspection, with no interpolated value. A heatmap or spectrogram cell appears only when the event already includes cell indices.
- The selection table pages the event's indices, 20 rows at a time. Linked selection is still two scatters and one histogram.
- Viridis and magma use the 256 Matplotlib 3.10.7 stops. Coolwarm is available. `colorMap` accepts under, over, and bad colors.
- Scatter interaction on worker-owned data replans from a spatial grid, and the first query may build that grid. Mutable caller buffers still scan. An unindexed point query records indices during the visibility pass.
- The renderer can upload a known dirty vertex span when that span is under three quarters of the buffer. A steady streaming append that evicts the front of the window still dirties the retained buffer, so that path remains a full upload.
- 3D picking builds its projected index in chunks and keeps a hit only when it passes the existing hit test.

## Same-machine measurements — 17 November 2026

These numbers are from one machine, before and after the engine change. They are not a universal speed claim, and they do not mean the product is faster overall.

`npm run benchmark` used Chrome 157.0.8103.79 headless, device pixel ratio 1, viewport 1000×700, and the hardware GPU path (`softwareGpuRequested` false): ANGLE Intel Graphics (0x00007D67) Direct3D11 on an Intel Core Ultra 9 275HX. Both the baseline and the later run were a 1,000,000-point scatter that stayed on density aggregation. Interaction p95 is the 95th percentile of 20 `setView`/`ready()` samples.

| | Baseline | 1.1.0 |
| --- | ---: | ---: |
| First render | 215.8 ms | 460.5 ms |
| Interaction p95 | 317.4 ms | 75.5 ms |

The first render is slower because the spatial grid is built on the first query. Other panel cases on the same machine were mixed: several first renders were slower, including the 1,000,000-point single-panel scatter in `npm run benchmark:panels`.

`npm run benchmark:streaming` requested SwiftShader (`softwareGpuRequested` true). Those timings are software-renderer numbers, not hardware FPS.

## Not in this release

SVG export, PDF export, pandas integration, lasso selection, twin axes, and symlog scales are not part of 1.1.0.

## Publication

Major version 1 still uses the [bounded automatic publication policy](v1.0.0.md#approved-v1-publication-policy--5-november-2026). Final publication needs `npm run package:release` from a clean commit that carries the `v1.1.0` tag, then reviewed gate reports bound to those exact archives. `npm run verify:next` writes local candidate archives and does not mark gates passed. Long-duration endurance, real screen-reader operation, and the five-person unaided pilot remain unverified. The 5 November 2026 `verify:next` result belongs to 1.0.0.

A later local `npm run verify:next` on 17 November 2026 passed in **80.024 seconds**, including build, candidate packaging, browser/offline checks and the installed wheel's Qt and Jupyter workflows. That run's manifest was a candidate from a dirty working tree at commit `00d9fbfd27586dc46c1650109ac6e6a93eb1a87c`, manifest SHA-256 `b3f5c96bbcbd87aa25460f5c1c5cf2d670d5d22569e75dc63fdca991a0e239d5`. It is not a final publication identity and it did not mark any release gate passed. [Report](../../artifacts/v1-verification/2026-11-17T16-32-43-575Z/report.json).
