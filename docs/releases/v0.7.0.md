# Vesora v0.7.0 — readable figures, intervals and shared inspection

v0.7 improves scientific chart readability and export control across the shared engine. It adds explicit interval bands, inspection of multiple lines at one cursor x, separate typography sizes and labeled color scales. Python, JavaScript and React expose the same scene features.

**Local developer preview, MIT licensed.** Build the wheel and npm archives from this checkout. Packaging does not publish to npm, PyPI or GitHub. WebGL2 remains required; Python desktop display uses QtWebEngine and NumPy remains optional. There are no new mandatory Python dependencies.

## Make figures readable at the size people use

Theme tokens now accept optional `titleFontSize`, `labelFontSize`, `tickFontSize` and `legendFontSize`, each from 8 through 32 logical pixels. The existing `fontSize` fallback remains in effect when these are omitted. Layout uses measured text to reserve plot margins and choose a tick density. Scalar and density layers accept `colorbarLabel` in JavaScript or `colorbar_label` in Python to show quantities and units.

The scientific README gallery uses one column, linked full-resolution PNGs, and explicitly chosen typography for previews. [`scripts/render_readme.py`](../../scripts/render_readme.py) produces all four images through Vesora itself: synthetic learning curves, count aggregation, a regular-grid surface and a sampled Lorenz trajectory. These examples are illustrations, not benchmark or measured model results.

## Show bounds without inventing statistics

```python
import vesora as vs

x = [0, 1, 2, 3]
fig = vs.figure(title="Synthetic interval", theme={"tickFontSize": 14, "labelFontSize": 16})
band = fig.fill_between(x, [2.8, 1.5, .8, .5], [3.6, 2.1, 1.2, .9], color="#3569c8")
fig.plot(x, [3.2, 1.8, 1.0, .7], label="Model A", color="#3569c8")
fig.set_axes(xlabel="Training step", ylabel="Loss", yscale="log")
fig.set_hover_mode("x")
fig.savefig("interval.png", width=1000, height=600, scale=2)
fig.save_html("interval.html")
```

`fill_between` / `fillBetween` is available on figures and 2D panels. Bounds are supplied by the caller; no confidence interval or other statistic is calculated. Data channels are `x`, `lower` and `upper`, with equal-length numeric arrays. x values must be finite and strictly increasing; finite bound pairs must satisfy `lower <= upper`. Nonfinite bounds and logarithmically invalid values create gaps. Supported axes are linear/log/time x and linear/log y. Empty and one-sample arrays are valid.

Band opacity defaults to `0.18`; accepted styles are `color`, `opacity` and `label`. Source updates validate before commit. Rendering preserves both interval bounds and breaks; bands themselves do not add point hover or rectangle selection. In React, a line series can provide `band: {lowerKey, upperKey, color?, opacity?}`. Its legend entry controls the line and band together.

## Compare original samples at one cursor position

Opt in with `fig.set_hover_mode("x")`, `fig.setHoverMode('x')`, or React `hoverMode="x"`. The default remains nearest-point hover. Participating visible 2D lines need numeric/time coordinates and finite, strictly increasing x values; categorical lines are unsupported.

The guide follows cursor x while each line reports its nearest original sample within the same valid run. Values are not interpolated or extrapolated, and missing-data gaps are not bridged. Source x is shown alongside y when samples are irregular. Hidden series do not participate. Touch can pin inspection; the focused chart supports Left/Right and Home/End navigation.

The JavaScript `xhover` event provides `cursorX`, pointer position and source-indexed line items. React adds `onXHover` and `renderXTooltip`, including explicit missing entries for visible series without a valid sample. Python stores the hover mode in the scene but does not receive per-pointer hover callbacks. Guides and tooltips remain transient and are excluded from exports.

## Export at an explicit logical size and raster scale

Python `savefig` and `savefig_async`, JavaScript `savefig` and React `exportPNG` accept `width`, `height` and `scale`. Width/height must be supplied together as safe integers of at least 200 × 180 logical pixels. Scale is a positive finite raster multiplier. For example, 1000 × 600 at scale 2 creates a 2000 × 1200 PNG.

Exports render at the requested logical size, with recalculated layout. Raster dimensions are rounded and checked against a 32,000,000-pixel area budget and active GPU limits. Invalid requests leave the live chart unchanged. Omitting all options preserves the existing mounted-size/effective-DPR behavior; omitted dimensions use the mounted size, and omitted scale uses the effective viewer DPR. Explicitly supply all three for predictable dimensions.

## Compatibility and scope

The runtime accepts scene protocols **1–6**. Bands, an explicitly configured hover mode, role typography tokens or colorbar labels promote a scene to protocol 6. Earlier-feature scenes retain their earlier protocol, and existing default theme snapshots do not gain role tokens. Export sizing is an operation parameter rather than serialized scene state. Offline HTML embeds source buffers and a matching engine, including band bounds and hover mode; application callbacks and live connections are excluded.

This release retains the existing 3D surfaces and scatter capabilities. Error bars, SVG/PDF output, 3D panels, arbitrary meshes, streaming and statistical interval estimation remain outside this scope. No frame-rate, memory or competitor-speedup claim follows from the feature list.
