# Vesora v0.3.0 — Compare and explain

Compare scientific data in a fixed 2D panel grid, navigate shared axes together, annotate the result, and save the complete layout as PNG or one interactive HTML file. Python and JavaScript use the same scene and rendering engine.

**Developer preview, prepared from source.** This document describes the v0.3 implementation and package workflow; it does not announce that GitHub assets have been published. WebGL2 remains required. The Python desktop dependencies, optional notebook/NumPy extras and GitHub-asset distribution model are unchanged.

## Compare a signal and its residual

```python
import math
import vesora as vs

x = [i / 100 for i in range(1000)]
fig = vs.subplots(2, 1, sharex=True, title="Signal and residual", height=800)
top, bottom = fig.panel(0, 0), fig.panel(1, 0)
top.plot(x, [math.sin(t) for t in x], label="Signal")
bottom.plot(x, [0.08 * math.sin(17 * t) for t in x], label="Residual")
top.set_title("Signal")
bottom.set_title("Residual")
bottom.set_axes(xlabel="Time (s)", ylabel="Residual")
bottom.axhline(0, color="#64748b")
note = bottom.text(2, 0.06, "Small oscillation", font_size=13)
note.update(text="Inspect this interval")
fig.bookmark("Overview")
bottom.set_axes(xlim=(2, 3))
fig.bookmark("Detail", note="Both panels follow the same x interval.")
fig.restore_bookmark("Overview")
fig.save_html("comparison.html")
```

In JavaScript, `subplots({rows: 2, cols: 1, shareX: true})` also returns a `Figure`; use `fig.panel(row, col)`, `panel.setView(...)` and `downloadHTML(fig, "comparison.html")`. See the [API reference](../api.md#compare-data-in-panels) for both language examples.

## Included in v0.3

- Fixed 2D grids with independent axes by default; `sharex`/`shareX` and `sharey`/`shareY` synchronize scale, automatic extent and explicit limits across all panels.
- Panel-specific titles and labels, mouse pan/zoom, hover and region-selection routing. One figure uses one WebGL context, one scheduler and one overlay canvas.
- Data-coordinate `text`, `axhline` and `axvline` annotations, with mutable update/remove handles. Text is plain text; annotations are clipped and do not change automatic data limits.
- Whole-layout bookmarks, reset, PNG export and self-contained HTML, including panels and annotations. Narrow host areas scroll over the fixed grid; PNG captures the complete drawing area.
- Three new [comparison examples](../../examples/web/compare.html) alongside the original 16, with 19 Python and 19 JavaScript snippets in the example checker.
- A reproducible single-panel versus four-panel benchmark for line/scatter workloads at 100,000 and 1,000,000 total source rows.

Shared axes do not imply linked brushing: selecting records in one panel does not highlight or filter another panel. Error bars, confidence bands, streaming, 3D panels, nested layouts, SVG/PDF and WebGPU remain outside this release.

## Compatibility

Existing single-panel calls, five plot types, layer handles, NumPy-free inputs, notebook and desktop hosts remain available. `subplots` returns the existing `Figure` type. Figure-level plotting and axis methods address the main, top-left panel; figure titles and exports apply to the whole layout.

Legacy scenes retain protocol `1`. Grids and annotations use protocol `2`; the new reader accepts both and rejects malformed panel references, incompatible dimensionality or incomplete view states before replacing a valid scene. Older engines reject v2 rather than silently dropping annotations or overlaying separate panels. Removing the last annotation does not downgrade a v2 scene.

The standalone envelope remains `formatVersion: 1` and includes a matching runtime. Previously exported v0.2 files keep their embedded runtime. Bookmarks store views rather than historical datasets, annotation state, styles or selections. Restoring a grid bookmark restores all panel views atomically.

## Build the packages

From a checkout with Node.js 22+ and Python 3.10+:

```bash
python -m pip install "setuptools>=77" wheel
npm ci
npm run build
npm run package:release
```

The output directory `dist/release-v0.3.0` contains:

- `vesora-0.3.0-py3-none-any.whl`
- `vesora-core-0.3.0.tgz`
- `vesora-discovery-demo.html`
- `vesora-comparison-demo.html`
- `SHA256SUMS.txt`

Install the wheel with `python -m pip install ./dist/release-v0.3.0/vesora-0.3.0-py3-none-any.whl`. Copy the tarball into a browser project and run `npm install ./vesora-core-0.3.0.tgz`. Package building does not publish to GitHub, PyPI or npm.

## Validate and measure

The release checks are documented in [development and measurement](../development.md): type checks, unit and Python tests, Python/JavaScript scene parity, all 19 examples, browser rendering, offline HTML, installed-package consumers, and separate real Qt/Jupyter host tests.

Local validation on Windows with Python 3.14.6 and Chrome software WebGL completed type checks, 65 unit tests, 142 ordinary Python tests, six real Qt tests, one real JupyterLab UI test, legacy/extended scene parity, all 19 examples in each language, and the offline HTML and engine/panel browser suites. The ordinary Python run skipped Qt tests; those tests passed in a separate enabled run. This local evidence does not establish that the new remote CI host jobs or every operating-system/graphics combination have passed. Installed-package validation also passed: the wheel was installed without dependencies in a clean virtual environment and the tarball in an offline npm consumer; both generated offline HTML with working bookmarks and PNG export, and installed TypeScript declarations passed NodeNext checking.

Run `npm run benchmark:panels` after building. It writes `artifacts/benchmark-panels.json`, recording the device, browser, renderer, source sizes, representations, first-render and zoom-to-ready latencies. Four-panel cases split a fixed total row budget across panels. Software WebGL results and synthetic examples do not establish a hardware FPS or universal speedup guarantee.

The recorded hardware run and its methodology are in the [v0.3 panel benchmark](../benchmarks/v0.3.0.md).
